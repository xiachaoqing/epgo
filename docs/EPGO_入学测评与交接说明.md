## 2. 当前可用流程

网站导航 / Hero / 公众号中的普通链接 → /epgo/assessment.html
→ 选择 KET → 填写孩子姓名或昵称（必填）、年级、教材经历、可选电话
→ 五部分 29 题，部分切换、整体已答进度、计时、草稿保存
→ 提交，漏答时确认；取消会定位第一道未答题，确认则空题记 0
→ 得分 / 正确率 / 已答数 / 各部分分数 / 复核提示
→ 复制报告给老师、打印成 PDF、或查看现有 App 套餐。

所有孩子信息、答案、结果仅存在当前浏览器，不自动提交给老师。页面已明确说明。无短信、无服务器测评记录、无收费测评订单、无教师后台评分功能。

普通链接：
- App 套餐：/epgo/?source=assessment#pricing（只带固定来源标记，不把手机号、姓名、分数写入 URL）
- 老师沟通：/epgo/#follow（复用现有关注公众号弹窗；家长主动发报告，不是预约成功）
- App 下载：/epgo/#download

source 参数当前只是链接标记，不代表已经接入统计或订单归因。
购买脚本在首次微信 OAuth 时会使用不含 query/hash 的回跳路径；这是现有行为，因此首次授权后可能回到首页顶部，需要家长再点激活套餐。未改 OAuth/支付逻辑。
PC 与普通手机浏览器可看套餐、打开弹窗；微信 JSAPI 支付仍要求微信环境。页面已增加这一说明。

## 3. 题库核验与限制

### KET 当前开放

来源：项目相邻 wx/资料/KET入学测试 试题.pdf 与 KET入学测试 (精品 对接KB4) 答案.pdf。
原件本身标注 A1 Movers / KET Placement Test，适用于精品班（对接 KB4）。用于进入 KET 学习前的基础筛查，有意区别于 KET 官方模拟考试，不能直接据此推断 KET/PET/FCE 等级。

五部分依次为 5 / 6 / 6 / 5 / 7 分，共 29 分。原卷 Part 6 开放表达未上线，未计入 29 分；听力和口语未测。Part 1 和 Part 5 已补充题图，词汇题改名「词汇选词」，保留英文句子、词库、故事与客观题。

修复：
- cloze 原只存 q.a，旧提交读取 q.key.some 会报错；统一读取 q.key 或 q.a。
- 不再用 includes 判答案，否则 banana 含 a、hospitalxxx 含 hospital 会错误得分。
- 英文答案去首尾空格、合并多空格、统一大小写和弯引号，再做完整候选答案匹配。
- Part 5 按答案 PDF 录入完整短语及可接受变体，不再把 coat / leav / surpris 当完整答案。
- 「hot and sunny」允许换序，但单独 hot 不计正确；其他候选可继续由老师核对。
- 清空填空内容后删除答案键，进度和漏答数正确减少。
- 去掉仅凭分数自动分配 KB4/KB5、声明 KET 合格/PET 优秀的规则，只显示本卷表现和教师复核提示。

### PET / FCE 保留草稿，暂不开放

QUIZZES 中仍保留两套原代码，未删除用户资料，但 AVAILABLE_LEVELS 仅为 ['ket']，UI 标记为试题校对中。startTest 和恢复本地记录都会检查可开放级别。

已确认的问题：
- PET / FCE Part 1 只有中文场景标题和选项，缺少要求阅读的原始短消息。
- 部分英文阅读被译成中文或缩写，改变了测量内容。
- PET 芭蕾阅读有提问信息在当前短文中缺失。
- FCE Leo 要一对一，当前答案 B 却是小组课，匹配条件矛盾。

开放前逐题核对原始材料、题干、选项和答案，补齐后由老师审核。不能仅将卡片改成可点击，也不能把「程序能计分」等同于题目有效。

## 4. 页面状态与数据

数据版本 3：
- epgo_assessment_draft_v3：version、level、profile、answers、currentPart、sec。
- epgo_assessment_result_v3：以上字段 + score、total、answered、partScores、createdAt。
- profile：name、grade、course、phone；answers 按 p0_q0 等稳定题目 ID。
- 题目内容或评分标准发生变化时，升级 STORAGE_VERSION 与键名，避免混用旧报告。
- 首页主动点击「继续上次测评 / 查看上次结果」恢复，不自动把上一位孩子的结果显示给新访客。
- 恢复成绩从保存的答案重新计算；损坏、版本不符、不可开放级别记录被忽略。
- localStorage 不可用时仍可答题出分，报告明确提示复制/截图；不声称已保存。
- 结果保存成功后才删除草稿；复制失败时提示截图或打印。

不读取或改写 jzt_openid、jzt_order、jzt_phone 等支付会话数据。
当前不做云同步，换设备/清缓存不能恢复；「复制报告」才会把可选电话包含在报告文本中，需家长自行发送。

## 5. 响应式与购买隔离

购买页：
- 小于等于 600px 单列套餐，601–960px 双列，大屏四列。
- 窄屏查询输入和按钮上下排列；弹窗限制可视高度、内部滚动；输入框 16px。
- 导航按空间收起；网格子项 min-width:0，二维码和按钮适配窄屏。
- 支持系统缩放、减少动态效果偏好、锚点预留固定导航高度。
- 不修改价格、plan_id、订单请求、微信授权、支付 SDK、支付结果跳转、账号开通/查询。

测评页：
- 手机按部分作答，材料紧邻题目；桌面长阅读采用材料/题目双栏。
- 原生 radio 支持键盘选择；部分按钮支持键盘；结果复制与打印。
- 套餐购买是结果页独立 CTA，老师复核与 App 购买均可主动选择。

## 6. 学习工具集合（已实现本地版）

入口为 `/epgo/tools.html`，首页 `#tools` 的日历和备忘录卡片已链接到对应工具。工具集合独立于支付页面，不读取订单、微信授权或 App 账号，也不会自动创建订单。第三方 App 没有接口，因此页面只保存家长手动录入的学习安排，不承诺自动同步 App 任务、点评、学生或续费状态。

| 工具 | 当前行为 | 本地数据 |
| --- | --- | --- |
| 今日概览 | 汇总当天日历安排，显示任务数、完成数、预计分钟；可快速进入日历或专注计时 | 读取日历 |
| 学习日历 | 手动添加日期、时间、内容、类型、预计分钟；完成/删除；按日期查看 | `epgo_tool_calendar_v1` |
| 英语备忘录 | 错题、生词、老师点评、计划等分类；例句、复习日期、搜索、删除 | `epgo_tool_memo_v1` |
| 我的单词本 | 单词、释义、例句；搜索；标记已掌握；删除 | `epgo_tool_vocab_v1` |
| 专注计时 | 15/25/45 分钟，开始、暂停、重置；完成提示 | 当前页面状态 |
| 测评报告 | 读取 `epgo_assessment_result_v3`，显示总分和各部分分数，并链接测评与套餐 | 只读测评结果 |
| 一寸证件照 | 上传本地图片，按 25×35mm 比例裁剪，缩放/移动后下载 JPG | 当前页面状态 |
| 图片压缩 | 调整 JPG 质量和最长边，浏览器本地生成压缩图片 | 当前页面状态 |
| 视频画面提取 | 上传本地视频，按时间点提取当前画面并下载 JPG | 当前页面状态 |

移动端和桌面端均已自适应；顶部工具卡片切换面板，手机为两列工具入口，表单与列表自动改单列。媒体工具只使用浏览器 File、Canvas 和 HTML5 Video API，当前不引入外部运行时依赖。
当前版本明确提示数据保存在当前浏览器，尚未实现导出/导入；云端版建立独立网站家长/孩子关系和 `/api/study` 命名空间，按归属鉴权。
网站账号和 App 账号不假设相同。通知作为后续单独能力，有权限和接收渠道后再实现。
学习工具不属于已售套餐承诺，不新增隐藏收费，不读写现有订单表。先验证家长每周使用情况，再决定云同步和收费。

视频工具边界：当前「视频提取」是用户选择本地视频后截取画面/封面，不是抖音、快手、小红书、B 站等平台的链接下载器。平台链接解析需要对应平台的官方授权、内容权利确认、服务端限流和存储策略；没有这些条件时不能用第三方接口或绕过平台限制来承诺下载。

测评线下兜底：答题页的「打印 / 保存题本 PDF」使用浏览器打印功能，家长可以保存当前题本；结果页允许选择照片或 PDF 做本机文件检查，但当前不会上传服务器、不会自动 OCR 判分。正式的「上传答题卡 → 老师复核」需要单独的受保护上传接口和教师后台，不能把本机预览误称为线上验证。
